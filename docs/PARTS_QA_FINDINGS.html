Fixed

Each reproduced, corrected, re-run clean, and pinned by a regression test

F1 A suspected unapproved part was issued to a job High Fixed Introduced here

Available → HoldNcm and Reserved → HoldNcm were missing from the transition graph, and the hold in open_discrepancy was guarded by can_transition_to — so when the transition was illegal it was skipped silently. Raising a discrepancy against shelf stock wrote the report, returned 201, and left the unit untouched.

The entire purpose of raising a discrepancy is to stop the part being used. It stopped nothing.

unit d0000000 starts available raise suspected-unapproved → HTTP 201 unit: available SUP flag t open discrepancies 1 ISSUE with an open SUP discrepancy → HTTP 200 unit: issued

Fixed. Both transitions are now legal, and a hold that cannot be applied refuses with 409 rather than passing quietly. Re-run: the same sequence now returns 409 a unit in hold_ncm cannot move to issued.

F2 An issued part could not be returned to the bin it came from High Fixed

issue leaves the unit recorded at its location. return requires a location, so the no-op guard fired on the ordinary case — putting a part back where it came from — and the operator had to invent a different bin to get it onto the shelf.

reserve → HTTP 200 status=reserved issue → HTTP 200 status=issued return → HTTP 400 the destination is the location the unit already occupies

Fixed. The guard now applies only to a pure relocation — the one movement that can actually be a no-op. This one is pre-existing, and the user guide I wrote earlier told people to use exactly the path that did not work.

F3 An inspection that checked nothing accepted the part Medium Fixed Introduced here

Every gate defaults to na, and nothing distinguished “not applicable” from “not assessed”. Posting an empty body released a unit from quarantine into serviceable stock with no evidence recorded at all — defeating the purpose of the record.

POST /units/{id}/inspections {} → HTTP 201 outcome=accepted status=available

Fixed. Nothing assessed now proposes quarantine and cannot support an acceptance. The refusal names that reason instead of listing an empty set of failed gates.

F4 /api/parts silently ignored pageSize Medium Fixed Introduced here

SearchPartsQuery was the only list query struct without rename_all = "camelCase", so it accepted page_size while every other list accepted pageSize. The wrong spelling fell back to the default rather than erroring.

?pageSize=3 → returned 26 pageSize=50 ignored ?page_size=3 → returned 3 pageSize=3

Fixed. A regression test now walks all five list query structs and fails if any one drifts from camelCase.

Still open

Found, reproduced, not yet addressed

F5 A validation error is reported as a service outage Medium Open

Any counted quantity at or above 1e9 overflows numeric(12,3) and surfaces as 503 server-side persistence is temporarily unavailable. The operator is told to retry something that can never succeed, and the log reads as an infrastructure fault rather than a typo.

counted=1e+09 → HTTP 503 server-side persistence is temporarily unavailable counted=1e+15 → HTTP 503 server-side persistence is temporarily unavailable

Fix: bound the quantity in the application layer and return 400 naming the limit.

F6 Role boundaries cannot be exercised on a developer machine Medium Open

Local mode is hardcoded to Role::Administrator with no override. The inspection buy-off — restricting who may release stock onto the serviceable shelf — is an airworthiness control, and it has never been exercised end to end. Only the predicate functions are unit-tested, which does not prove the handlers wire them correctly.

Fix: an environment variable selecting the local role, so every gated path can be walked as each role.

F7 The exported template fails its own import validation Medium Open

The export doubles as the import template, so an exported file should re-import cleanly. It does not: the template carries the legacy coc trace value, which is readable on historical records but deliberately not writable.

POST /imports/preview (the system’s own template) row 2 trace_type 'coc' is not a document this system records

Fix: either map coc to a writable value on export, or accept it on import as a legacy passthrough.

F8 Ledger free text is unbounded Low Open

A movement accepted 20,000 characters of notes and stored them whole. Nothing caps the field.

F9 Sub-resources answer 200 for a unit that does not exist Low Open

GET /units/{id} returns 404 for an unknown unit, but /units/{id}/inspections and /units/{id}/events return 200 with an empty list. Not a leak — the scoping is correct — but a caller cannot tell “no records” from “no such unit”.

One correction

A finding I reported and then withdrew

Withdrawn

I initially flagged /units/{id}/inspections and /units/{id}/events as cross-tenant leaks because both answered 200 for another organisation’s unit. Re-testing with a foreign unit that genuinely had an inspection and a ledger entry attached showed both return an empty list — the scoping is correct and nothing leaked. What remains is the far smaller status-code inconsistency recorded as F9.
